# Handoff: простой MVP Evolution Console

Дата: 03.08.2026

Ветка: `codex/evolution-console-simple-mvp`

База: `origin/main@6f28176`

Версия карточки: `0.11.1`

## Что изменено

Первый экран теперь управляет автоматизациями пользователя, а не внутренними
агентами Extella. Русский заголовок — `Центр Управления Агентами`, рядом всегда
видно каноническое название поверхности `Evolution Console`.

- Сводка делит установленные автоматизации на четыре взаимоисключающие группы:
  `работают`, `остановлены`, `статус неизвестен`, `нужна помощь`.
- `Мои автоматизации` и `Каталог` остаются разными режимами.
- Закрытая карточка показывает название, назначение, человеческий статус,
  максимум одно главное замечание и один следующий шаг.
- Остановленная владельцем автоматизация не считается сломанной только из-за
  `NOT_RUNNING`; неизвестное состояние не считается успехом.
- В раскрытой карточке на первом уровне видны последний и следующий запуск,
  версия и состояние защиты данных. Четыре B4-факта, расписания, состав,
  MCP, Agent Cabinet, коды и гейты сохранены под `Для специалиста`.
- Agent Cabinet открывается только из конкретного внутреннего агента в составе
  автоматизации. Новый кабинет не создавался.
- Верхняя пустая вкладка Evolution Lab удалена. Evolution Lab доступен только
  для точного change context, привязанного к текущему snapshot; без него
  маршрут возвращает в Evolution Console.
- Свёрнутый блок `Другие задачи` содержит ровно четыре человеческих входа:
  проблемы, зависимости, изменение нескольких автоматизаций и история.
- PRE/POST и число внутренних агентов больше не входят в сводку парка.
  Криптография и masking engine не менялись.
- Русская и английская копия обновлены синхронно.
- После проверки в Xtel убрана вторая шапка внутри iframe: название, логотип и
  навигацию уже показывает shell Extella. Поверхность приведена к актуальному
  `DESIGN_CODE.md`: Nunito / Source Serif 4, радиусы 12/8/999, без теней.
- Недоступные карточки текущего устройства больше не превращаются в ложный
  `0`: счётчики показывают `—`, а пустое состояние предлагает повторить
  проверку или открыть каталог.

## Честные границы

- Реестр и карточки остаются read-only. UI не обещает включение, обновление или
  откат, пока соответствующего trusted action нет.
- `Следующий запуск` берётся только из фактического runtime `next_run`; cron не
  интерпретируется и вымышленная дата не подставляется.
- Защита данных остаётся `не удалось проверить`, если нет полного валидированного
  snapshot по всем внутренним агентам автоматизации.
- Evolution Lab не открывается без `change_id`, `candidate_id`, точного списка
  автоматизаций и совпадающего `registry_snapshot_id`.
- На проверенном Mac строгий локальный сканер видит 16 карточек, включая
  `extella_1c_agent`, `extella_contract_agent` и `extella_travel_agency`.
- Внешняя зависимость доставки закрыта 04.08.2026: Expert
  `_etb_evolution_registry_scan_v1` включён в установку/обновление пака,
  зарегистрирован на рабочем аккаунте и проверен исполнением на живом списке
  из 16 карточек. Клиентская копия и канонический source в `toolbar-src`
  объявлены парой в copy gate, поэтому расхождение теперь останавливает выпуск.

## Что сделать интегратору

1. Сверить ветку с актуальным `origin/main`; системную карточку заново не
   создавать — она уже находится в `main`.
2. Review и merge `codex/evolution-console-simple-mvp`.
3. В чистом checkout нового `origin/main` повторить `npm test` и release build.
4. Выполнить канонический install/deploy только из чистого `main`.
5. В Xtel проверить:
   - первый экран и четыре счётчика;
   - `Мои автоматизации` / `Каталог`;
   - карточки 1С, Kazakh Lawyer и турагентства;
   - раскрытие `Для специалиста` и Agent Cabinet;
   - RU/EN, light/dark, ширину `390px`;
   - отсутствие Evolution Lab без точного изменения.

## Rollback

Откатить merge-коммит ветки, повторить официальный release build и install из
чистого `main`. Изменений в Agent Genome, Agent Passport, Shared Genes, ledger
или данных автоматизаций эта ветка не выполняет.
